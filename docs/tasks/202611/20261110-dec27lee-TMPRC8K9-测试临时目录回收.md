## 需求描述

用户报「`%TEMP%` 下积了 212 个 `lc-dingtalk-sent-*` 目录」，确认可以清理。

顺手查了同一目录的全部同族残留，规模比报的大两个数量级。

## 现状（本机实测，2026-11-10）

| 项 | 数 |
| --- | --- |
| `%TEMP%\lingcub-*` 目录 | **36858 个** |
| `%TEMP%\lc-dingtalk-sent-*` 目录 | 212 个 |
| 最早 | 2026-11-04 |
| 单个内容 | 1–2 个测试夹具文件 |

成因：用例里普遍写 `mkdtempSync(join(tmpdir(), 'lingcub-xxx-'))`，**建了没人删**。
`pnpm test` 每跑一次全量，按用例数新增几十个目录；212 个 `lc-dingtalk-sent-*`
就是 `tests/specs/plugins/dingtalk-sent.test.ts` 一个用例跑了 212 次。

## 技术设计

不在 40 多个用例文件里挨个补 `rmSync`（补完还是会漏，且是体力活）。**在入口收口**：

`scripts/test-run.mjs` 把子进程的 `TEMP/TMP/TMPDIR` 指到 `<tmpdir>/lingcub-test/run-<pid>-<ts>`，
跑完（含异常与 Ctrl-C）整棵删掉；父目录空了也一并收。用例代码一行不改。

判据是这三条同时成立：`os.tmpdir()` 认环境变量（Node 在 Windows 读 `TEMP`/`TMP`）、
测试全是顺序起子进程、每个用例的夹具只活在这一次运行里。

| 项 | 结果 |
| --- | --- |
| `pnpm test` | **631 pass / 0 fail**，与改造前同数 |
| 跑完 `%TEMP%\lingcub-test` 残留 | 0 |
| 跑完新增 `lingcub-*` 目录 | 0（改造前每次几十个） |
| 存量清理 | `removed=37070 failed=0 total=37070`，剩余 **0** |

`test-run.mjs` 第一版把 TS 的 `(): void =>` 写进了 `.mjs`，`pnpm test` 直接语法报错；
改掉后重跑才是上面的结果。父目录用 `rmSync(recursive:false)` 删不掉空目录
（Node 对目录要求 `recursive`），换 `rmdirSync` 才收干净——两次都是跑出来的，不是推的。
