## 需求描述

把桌面面板从“固定配置页”改成可扩展的工作台：插件可以贡献导航菜单、独立页面和公共页面的插槽内容。
第一阶段先做**稳定的 UI 贡献契约 + 最小宿主**，不追求插件前端热更新、沙箱或完整设计系统。

约束：

- 不为某个具体插件写死 UI；宿主只认识 slot 名和贡献声明。
- 插件 UI 不进入内核（`src/kernel`/`src/domain`/`src/routing` 不 import 插件）。
- 贡献失败不能拖垮面板；单个插件页面/插槽错误只影响自己。
- 默认只允许本机 `127.0.0.1` 面板；插件页面先按可信本地代码处理，但要有明确的注入边界。
- 复用现有 `src/desktop/server.ts` 的启动/令牌/打开窗口方式，不引入前端构建链。

## 技术设计

参考 DSH：DSH 把前端 bundle 放在插件 package 的 `exports["./client"]`，Host 生成 boot 图，浏览器端用 `__ModuleLoader__` + slot registry（`inject/register`）把组件插入 `main`、`sidebar.panellist`、`shell.bottom` 等点分层级插槽；插件 bundle 与宿主同源执行，隔离靠模块表与静态路由白名单，没有权限系统。

本项目不引入前端构建链，采用**同构的声明 + 静态宿主**最小实现：

1. **贡献描述**：插件目录可选 `ui.json` 声明 `nav`、`slots`；不放进 manifest，避免内核清单闭集变化。
2. **发现**：面板启动/请求 `/api/ui` 时扫 `PLUGIN_DIR`，只收 `pluginStatuses` 中已启用的插件；不调用插件 `setup`，不产生运行时副作用。
3. **页面**：插件静态资源在 `<plugin>/ui/`；`/api/ui` 给出 URL，宿主 `/plugin-ui/<plugin>/<page>` 提供。
4. **插槽**：宿主内置 `main.header` / `main.footer`，用沙箱 iframe 挂载；插件页面不能直接读写宿主 DOM。插件静态页走免宿主令牌路由，iframe 里不携带宿主 token。
5. **失败隔离**：`ui.json` 非法、页面缺失、路径穿越都只记 `errors` 并跳过该条；单插件不影响宿主。
6. **构建**：`scripts/copy-assets.mjs` 把 `ui.json` 和 `ui/**` 的 html/css/js/图片字体复制进 `dist/plugins`。
